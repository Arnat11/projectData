# Airify Store

ร้านค้าอุปกรณ์ดูแลอากาศแบบ Node.js และ MongoDB มีหน้าร้าน บัญชีลูกค้า หน้าผู้ดูแล และ API ในโปรเจกต์เดียวกัน

## เริ่มใช้งานกับ MongoDB Atlas

1. ติดตั้ง Node.js 20.19 หรือใหม่กว่า
2. คัดลอก `.env.example` เป็น `.env`
3. ใน MongoDB Atlas สร้าง database user ที่มีสิทธิ์ `readWrite` กับฐานข้อมูล `airify_store` แล้วอนุญาต IP ของเครื่องใน Network Access
4. นำ connection string จาก Atlas มาใส่ใน `MONGODB_URI` ใน `.env` แทนค่า `cluster.example.mongodb.net` และใส่ชื่อผู้ใช้กับรหัสผ่านของ database user หากมีอักขระพิเศษในชื่อผู้ใช้หรือรหัสผ่าน ให้ URL-encode ก่อนใส่ใน URI
5. เปลี่ยน `ADMIN_USERNAME`, `ADMIN_PASSWORD` และ `SESSION_SECRET` ใน `.env` เป็นค่าที่คุณตั้งเอง รหัสแอดมินต้องยาวอย่างน้อย 10 ตัวอักษร บัญชีนี้สร้างจากค่าภายใน `.env` โดยไม่มีรหัสผ่านเริ่มต้นในโค้ด
6. เปิด Terminal ในโฟลเดอร์โปรเจกต์ แล้วรัน:

   ```sh
   npm install
   npm start
   ```

7. เปิด `http://localhost:3000`

เมื่อเชื่อมต่อฐานข้อมูลครั้งแรก ระบบจะสร้าง index และเพิ่มสินค้าเริ่มต้น 30 รายการ หาก collection `products` ยังว่างอยู่ สินค้าและคำสั่งซื้อหลังจากนั้นอ่านและเขียนกับ MongoDB

## บัญชีและหน้าเว็บ

- ลูกค้าสมัครและเข้าสู่ระบบที่ `/account.html` ลูกค้าดูรายการสั่งซื้อของบัญชีตัวเองได้
- ผู้ดูแลเข้าสู่ระบบที่ `/admin.html` โดยใช้ `ADMIN_USERNAME` และ `ADMIN_PASSWORD` จาก `.env`
- API ตรวจ role ของบัญชีทุกครั้ง ลูกค้าไม่สามารถเรียก API จัดการสินค้า หรือดูคำสั่งซื้อของคนอื่นได้
- ผู้ดูแลเพิ่ม แก้ไขราคา/ข้อมูล/สต็อก และลบสินค้าได้จากหน้าจัดการ การเปลี่ยนแปลงเขียนลง MongoDB
- ลูกค้าเลือกสินค้าและสั่งซื้อได้ คำสั่งซื้อกับข้อมูลจัดส่งจะถูกบันทึกลง MongoDB และสต็อกถูกตัดระหว่างบันทึก
- ต้องใช้ MongoDB Atlas หรือ MongoDB แบบ replica set สำหรับการบันทึกคำสั่งซื้อแบบ transaction; ถ้าเชื่อมต่อ MongoDB แบบ standalone ระบบมีขั้นตอนชดเชยสต็อกกรณีบันทึกไม่สำเร็จ

## ไฟล์ตั้งค่า

อย่าแชร์หรือ commit `.env` เพราะมี MongoDB URI และรหัสแอดมิน ใช้ `.env.example` เป็นแม่แบบแทน หากเปลี่ยนรหัสผ่านแอดมินใน `.env` แล้วรีสตาร์ตเซิร์ฟเวอร์ ระบบจะอัปเดตรหัสผ่านบัญชีผู้ดูแลให้ตรงกับค่านั้น
